# 023 - Few-shot Prompting 실험

**예시 개수에 따라 결과 형식과 품질이 어떻게 달라지는가**

---

## 목적

Few-shot Prompting은 AI에게 예시를 주고 원하는 출력 형식을 학습시키는 기법.  
예시 개수(0개/1개/3개)에 따라 결과가 어떻게 달라지는지 직접 비교.

System Prompt 실험(22일차)과 함께 프롬프트 엔지니어링의 핵심 기법.

---

## 실험 조건

**동일한 요청:** `MovieFinder의 WatchHistoryRepositoryImpl.kt에서 버그를 찾아줘.`

| 단계 | 예시 수 | 방식 |
|------|--------|------|
| 0-shot | 0개 | 예시 없이 바로 요청 |
| 1-shot | 1개 | 버그 리포트 예시 1개 제공 |
| 3-shot | 3개 | 버그 리포트 예시 3개 제공 |

---

## 결과 비교

| 구분 | 0-shot | 1-shot | 3-shot |
|------|--------|--------|--------|
| 발견 버그 수 | **3개** | 2개 | 2개 |
| 출력 형식 | 자유 형식 | 예시 형식 따름 | 예시 형식 따름 |
| 수정 코드 포함 | 있음 | 있음 | 있음 |
| 응답 간결성 | 길고 상세 | 중간 | **가장 간결** |
| 형식 일관성 | 낮음 | 높음 | 높음 |

---

## Few-shot의 진짜 효과

예상과 다른 결과가 나왔다.

**예상:** 예시가 많을수록 더 많은 버그를 발견할 것
**실제:** 버그 발견 수는 0-shot이 가장 많았고, 1-shot과 3-shot은 비슷했다

Few-shot의 효과는 **"더 많이 찾는 것"이 아니라 "원하는 형식으로 일관되게 출력하는 것"**이었다.

---

## 실용적 사용 가이드

| 상황 | 추천 방식 |
|------|---------|
| 최대한 많이 찾아야 할 때 | 0-shot |
| 특정 형식으로 반복 생성 | 1-shot 이상 |
| 팀 내 AI 출력 표준화 | 3-shot + System Prompt 조합 |
| 보고서, 이슈 티켓 자동 생성 | Few-shot 템플릿화 |

---

## 22일차와 연결해서 보면

| 기법 | 효과 |
|------|------|
| System Prompt (역할+제약+형식) | 분석 깊이 향상 |
| Few-shot (예시 제공) | 출력 형식 일관성 향상 |
| **둘 다 조합** | 깊이 + 형식 모두 제어 가능 |

프롬프트 엔지니어링의 핵심은 **System Prompt로 역할과 제약을 설계하고, Few-shot으로 출력 형식을 고정**하는 조합이다.

---

## 느낀 점

예시를 많이 줄수록 더 좋은 결과가 나올 거라 예상했는데 틀렸다. 오히려 0-shot이 버그를 더 많이 발견했다.

Few-shot은 품질을 높이는 게 아니라 **형식을 통제하는 도구**다. 팀 내에서 AI 출력을 표준화하거나, 동일한 형식의 문서를 반복 생성할 때 가장 유용하다.
