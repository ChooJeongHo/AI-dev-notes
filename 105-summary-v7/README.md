## 7차에서 배운 핵심 교훈

**"같은 결과도 원인은 매번 확인해야 한다"**
098/099/100(클린의 세 가지 다른 이유), 101/102(같은 결론, 다른 원인), 101/103/104(같은 증상, 다른 원인)까지 반복 확인됐다.

**"반복되는 오탐/결함은 도구 자체를 고쳐서 원천 차단한다"**
098일차에서 검증 스킬(SKILL.md)을 직접 수정한 것도 이 원칙의 연장선이었다.

**"좋은 구조/설계 결정은 의도하지 않은 곳에서도 이득을 낸다"**
099일차와 100일차가 같은 패턴을 두 번 보여줬다.

**"정적분석을 전부 통과해도 실제 사용자 흐름을 끝까지 따라가야 한다"**
103일차의 popBackStack 오용은 실기기 UI 흐름에서만 드러났다.

**"AI의 짐작은 검증 없이 믿으면 위험하다"**
095일차에서 잘못된 엔드포인트 짐작을, 결국 사람이 직접 확인해서 바로잡았다.
