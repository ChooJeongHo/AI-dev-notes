# 024 - Chain of Thought 프롬프팅 실험

**"단계별로 생각해줘" 한 마디가 분석 깊이를 어떻게 바꾸는가**

---

## 목적

Chain of Thought(CoT) 프롬프팅은 AI에게 결론을 바로 내리지 않고 단계별로 생각하게 강제하는 기법.  
22일차(System Prompt), 23일차(Few-shot)에 이어 프롬프트 엔지니어링 3부작 완성.

---

## 실험 조건

**동일한 요청:** `MovieFinder의 현재 아키텍처에서 가장 큰 문제점과 개선 방향을 알려줘.`

| 단계 | 방식 |
|------|------|
| 일반 요청 | 바로 답해줘 |
| CoT 요청 | 1~5단계 순서로 생각하면서 답해줘 |

---

## CoT 프롬프트 구조

```
답하기 전에 다음 순서로 단계별로 생각해줘:
1단계: 현재 아키텍처 구조 파악 (레이어별 파일 수, 의존성 방향)
2단계: 각 레이어에서 발견되는 패턴 분석
3단계: 문제점 도출 (근거와 함께)
4단계: 리팩토링 비용 대비 효과 판단
5단계: 최종 개선 방향 제시
```

---

## 결과 비교

| 구분 | 일반 요청 | Chain of Thought |
|------|---------|-----------------|
| 발견 문제 수 | 3개 | **4개** |
| 근거 제시 | 간략함 | **파일명 + 라인 수까지 명시** |
| 레이어별 파일 수 분석 | 없음 | **정확히 집계** |
| ViewModel 파라미터 수 | 언급만 | **전체 표로 정리** |
| 우선순위 판단 | 간략함 | **비용/효과 매트릭스** |
| 수정 코드 예시 | 없음 | **있음** |

---

## CoT에서만 발견된 것들

**일반 요청에서 놓친 문제 2개:**

---

## CoT가 효과적인 이유

일반 요청은 AI가 패턴 매칭으로 바로 답을 내려요. 자주 보이는 문제는 잘 잡지만 숨겨진 문제는 놓쳐요.

CoT는 AI가 **코드를 실제로 읽고 → 분석하고 → 근거를 쌓고 → 판단하는 과정을 강제**해요. 덕분에 레이어별 파일 수, ViewModel 파라미터 수 같은 구체적인 수치가 자동으로 나왔어요.

---

## 프롬프트 엔지니어링 3부작 정리

| 기법 | 효과 | 언제 쓸까 |
|------|------|---------|
| System Prompt (22일차) | 분석 깊이 + 형식 제어 | 일관된 품질 반복 생성 |
| Few-shot (23일차) | 출력 형식 일관성 | 팀 내 표준화, 반복 생성 |
| Chain of Thought (24일차) | 근거 있는 깊은 분석 | 복잡한 판단, 아키텍처 결정 |

**최강 조합:** System Prompt(역할+제약) + Few-shot(형식) + CoT(단계별 사고) 세 가지를 동시에 적용하면 전문가 수준의 일관된 결과물을 얻을 수 있다.

---

## 느낀 점

"단계별로 생각해줘" 한 마디를 추가했을 뿐인데 놓쳤던 문제 2개를 추가로 발견했다.

CoT의 핵심은 **AI가 결론을 서두르지 못하게 막는 것**이다. 단계를 밟도록 강제하면 AI도 중간에 발견하는 것들이 생긴다.

복잡한 의사결정, 아키텍처 검토, 기술적 트레이드오프 판단 같은 상황에서 특히 효과적이다.
