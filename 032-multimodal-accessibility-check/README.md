# 032 - 멀티모달 활용 — 스크린샷 → 접근성 점검 자동화

**이미지를 입력으로 주면 AI가 WCAG 기준으로 접근성 문제를 분석하는 실험**

---

## 목적

31일차 멀티모달 실험(스크린샷 → Compose 코드)의 연장선.  
이번엔 UI 코드 생성이 아닌 **접근성(Accessibility) 점검** 관점으로 멀티모달 활용.

---

## 실험 방법

Claude Code 터미널에서 **Control+Option+V** 로 홈 화면 스크린샷 붙여넣고:

```
이 화면에서 접근성(Accessibility) 문제가 있는 부분을 찾아줘.
색상 대비, 터치 영역 크기, 텍스트 가독성, contentDescription 누락 여부 등
WCAG 기준으로 분석해줘.
```

---

## 1단계 — 이미지 분석 결과

스크린샷만 보고 발견한 문제들:

| 심각도 | 문제 | WCAG 기준 |
|--------|------|---------|
| 🔴 심각 | 평점 배지 contentDescription 누락 ("6.7"만 읽힘) | 1.1.1 |
| 🔴 심각 | 하단 네비게이션 아이콘 레이블 누락 | 4.1.2 |
| 🔴 심각 | 영화 포스터 contentDescription 누락 | 1.1.1 |
| 🟡 중간 | 개봉일 텍스트 색상 대비 부족 (3.5:1, 기준 4.5:1) | 1.4.3 |
| 🟡 중간 | 비선택 탭 텍스트 대비 확인 필요 | 1.4.3 |
| 🟡 중간 | 평점 배지 터치 영역 32dp (권장 48dp 미달) | 2.5.5 |
| 🟢 낮음 | 영화 카드 요소 포커스 파편화 | 1.3.1 |

---

## 2단계 — 코드 레벨 검증

Claude Code로 실제 코드 확인:

```
접근성 분석에서 발견된 문제들을 수정해줘.
평점 배지 contentDescription, 하단 네비게이션 레이블,
카드 포커스 통합 등을 수정하고 커밋해줘.
```

**결과: 이미 모두 구현되어 있었음!**

| 항목 | 상태 |
|------|------|
| 포스터, 평점 배지 `importantForAccessibility="no"` | ✅ 이미 적용 |
| 카드 통합 contentDescription `"%1$s, 개봉일 %3$s, 평점 %2$.1f"` | ✅ 이미 적용 |
| 하단 네비게이션 `android:title` 4개 항목 | ✅ 이미 적용 |

---

## 핵심 발견 — 이미지 분석의 한계

**스크린샷만으로는 코드 레벨 접근성 구현 여부를 알 수 없다.**

```
이미지 분석 → 시각적으로 보이는 문제만 발견
    ↓
코드 레벨 검증 → 실제 구현 여부 확인
```

이미지 분석이 "심각"으로 분류한 문제들이 실제로는 이미 잘 구현되어 있었다.

---

## 멀티모달 접근성 점검의 올바른 활용법

| 단계 | 도구 | 역할 |
|------|------|------|
| 1단계 | Claude.ai / Claude Code (이미지) | 시각적 문제 빠르게 탐지 |
| 2단계 | Claude Code (코드 분석) | 실제 구현 여부 코드 레벨 검증 |
| 3단계 | TalkBack 직접 테스트 | 실기기에서 최종 확인 |

이미지 분석은 **빠른 1차 스크리닝** 용도로, 코드 레벨 검증과 병행해야 한다.

---

## 느낀 점

접근성 문제를 스크린샷 하나로 빠르게 탐지할 수 있다는 점은 유용했다. 하지만 이미지만으로는 코드에 `contentDescription`이 있는지, `importantForAccessibility`가 설정됐는지 알 수 없다.

오히려 이번 실험의 진짜 발견은 **MovieFinder가 접근성을 이미 잘 구현하고 있었다**는 것이다. 이미지 분석이 발견한 "문제"들이 코드 레벨에서는 이미 해결되어 있었다.

**결론:** 멀티모달 접근성 점검은 "빠른 시각적 스크리닝 → 코드 레벨 검증" 2단계로 활용하는 게 올바른 방식이다.
