## 목적

138일차에는 gold가 있는 시간 분할 시험으로 LLM(`claude -p`)과 규칙 점검기를 비교해 **차이 +1사이트, "LLM이 낫다는 증거는 없다"** 로 끝났다. 다음 질문은 실용적이다.

> **gold가 없는 지금의 `main`에서 동결한 두 점검기를 그대로 돌리면 어떤 경고가 나오고, 그 경고는 얼마나 맞고, 진짜 낡은 줄을 고칠 수 있는가?**

- 138의 코드·프롬프트(P2)·집계는 **수정하지 않는다**(동결 해시 대조). 바꾸는 것은 대상(현재 `main`)과 판정 방식(사람의 전수 판정)뿐이다.
- 정답이 없으므로 재현율은 "합쳐서 찾은 낡은 줄"을 분모로 쓰는 **풀링 상대값**이고, 둘 다 놓친 줄은 분모에 들어가지 않는다. 이 한계는 처음부터 적었다.
- 예측은 **점검기를 돌리기 전에 해시로 사전 등록**한다. 깨질 수 있게 쓰는 것이 목적이다(P5의 정의를 실행 전에 고쳐 둔 이유).
- 판정은 탐지기를 봉인한 채 줄 원문만 보여 받는다(맹검). 판정 결과로 문서를 고치는 PR을 만든다.

원칙은 이전과 같다.
- **읽기 → 설계 → 롤백 조건 합의 → 실행**. 숫자·날짜 기준이나 롤백 조건이 걸리면 해석하지 않고 멈추고 묻는다. 기준 재정의는 이유를 적고 승인 후에만 한다.
- 저장소 변경(push·PR·merge)은 diff를 보여 주고 승인을 받는다. 일차 요약은 `CLAUDE.md`가 아니라 `DEVLOG.md`에만 쓴다.
- 핀 값은 앞 8자만, 요청 URL·키는 출력하지 않고, 기기 설정은 건드리지 않고, 임시 파일은 scratchpad에만, 삭제는 리터럴 경로로 허락 후에만 한다.
- checkout·switch·reset·stash는 쓰지 않고 과거 상태는 `git show`·`cat-file`로만 읽는다.
- **표본 확인은 원문을 보여 주고 사용자가 판단한 뒤에만 "확인"이라고 쓴다.** 확인을 거치지 않은 것은 "확인을 거쳤다"고 쓰지 않는다.

## 오늘 배운 것 — 한 줄 정리

1. **정답이 없는 곳의 평가는 "분모를 어떻게 만드는가"가 결과를 정한다.** 풀링 재현율은 분모 밖의 놓침(둘 다 놓친 2줄)을 못 본다. P5의 별도 판정이 그 구멍을 일부 메웠다.
2. **예측을 "깨질 수 있게" 쓰자 실제로 깨졌다.** P5의 처음 정의는 놓침을 조용히 "해당 없음"으로 만들었을 것이다. 실행 전에 구멍을 고쳐 둔 덕에 불성립이 드러났다.
3. **규칙의 오탐은 "문장이 차이를 올바르게 설명하는 줄"에서 났고, 둘 다 놓친 줄은 "최신 정식판은 X" 같은 외부 사실 서술이었다.** 토큰 대조형 점검기와 문장 의미를 읽는 점검기의 범위가 다르다는 단서다(방향성).
4. **이번 표본에서는 LLM이 더 맞혔지만(15/15 대 10/12) 우열을 말하지 않는다.** 구간이 겹치고(78.2~100 대 51.6~97.9), 사실이 7개이고, 판정이 독립이 아니다. 138의 "증거 없음"과 방향이 달라 보이지만 정의·표본이 달라 합치지 않는다.
5. **판정 화면에서 도우미가 라벨을 제안하면 맹검 설계가 깨진다.** 판단 기준만 설명하고 라벨은 사용자가 정해야 한다. 이번에는 사후에 한계로 적었을 뿐 설계를 지키지 못했다.
6. **점검 시점과 수정 시점 사이에 `main`이 움직인다.** 로컬 `main`(fetch 없음)으로 점검하기로 한 결정이 PR 직전 diff 재작성(AGP 9.5.0 → 9.5.1)을 불렀다. PR 직전 원격 확인 계획이 이를 잡았다.
7. **문장 안의 숫자만 바꾸면 거꾸로 틀려지는 줄이 있다.** "9.4.1이 최신 정식판, 9.5.0은 rc"를 숫자만 바꾸면 모순이다. 그런 줄은 문장을 고쳐 쓰고 확인하지 못한 사실은 "미확인"으로 적었다.
8. **한 줄의 한계 추가가 다른 표현의 모순을 드러낸다.** "사용자 단독 판정"과 "판정 독립성 한계"가 한 문서에 공존할 수 없었고, PR 전에 정리했다.
9. **반복 호출은 캐시가 비용을 정한다.** 1회차 $0.0792, 2·3회차 약 $0.010. 같은 입력을 3회 돌리는 설계가 12호출을 $0.40에 맞췄다.
10. **LLM은 12쌍 모두 같은 판정(Jaccard 1.0)이었다.** 138(96쌍 중 15쌍 다름)과 달리 이번에는 비결정성이 드러나지 않았다. 단위가 4개뿐이라 해석하지 않는다(P7 불성립).
11. **오래 기다린 설계는 실행 전에 기준이 바뀐다.** 73시간 뒤에 CLI가 바뀌어 기준을 재정의해야 했다. 단계 전환마다 CLI 확인 규칙이 잡아냈다.
