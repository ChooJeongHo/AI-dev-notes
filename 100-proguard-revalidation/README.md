# 100 - ProGuard 재검증 — 검증 스킬 3부작(089/091/092) 완결

**095~097일차 KMRB 코드에 릴리즈 빌드 전용 keep 규칙 누락이 있는지 확인 — 실질 이슈 0건, 실제 릴리즈 빌드로 검증까지 완료**

---

## 목적

089/091/092일차 검증 스킬 3부작 중 마지막으로 남아있던 proguard-validator를 095~097일차 KMRB 코드 기준으로 재실행한다. 이걸로 100일차에 3개 스킬 전부가 최신 코드 기준으로 재확인된다.

---

## 검증 결과 — 신규 keep 규칙 불필요

095~097일차에 추가된 KmrbRatingXmlParser.kt, KoreanRatingRepositoryImpl.kt, GetKoreanRatingUseCase.kt, FilterMoviesByKoreanRatingUseCase.kt를 확인했다.

092일차에서 발견했던 "릴리즈 빌드 전용 keep 규칙 누락" 패턴이 이번엔 나타나지 않았다.

이유: 095일차에서 XmlPullParser 대신 SAXParser를 선택한 건 "새 라이브러리를 추가하지 않으면서 유닛 테스트 가능성을 확보하기 위해서"였다. 그 결과로 KMRB 응답 파싱은 kotlinx.serialization의 리플렉션 기반 역직렬화를 쓰지 않고, 파서가 XML 태그를 직접 읽어서 평범한 생성자 호출로 도메인 객체를 만드는 방식이 됐다. 092일차에서 keep 규칙이 필요했던 이유(R8이 리플렉션으로 참조되는 필드/클래스명을 난독화하면 역직렬화가 깨질 수 있음)에 해당하는 리플렉션 경로 자체가 KMRB 쪽엔 없었다.

---

## 검증 방식 — 실제 릴리즈 빌드로 재확인

089/091일차 재검증(099/098일차)과 마찬가지로, "이슈가 없다"는 결론도 실제로 검증했다.

```
./gradlew assembleRelease (minifyEnabled=true)
    ↓
릴리즈 APK 설치
    ↓
KMRB 등급 정상 로딩 확인 (상세 화면 + 검색 필터 + 박스오피스 배지)
```

릴리즈 빌드에서도 KMRB 관련 기능 전부 정상 동작.

## 089/091/092 검증 스킬 3부작 — 095~097 기준 재실행 결과

| 원본 일차 | 재실행 일차 | 결과 |
|---|---|---|
| 089 (network-layer) | 099 | 실질 이슈 0건 |
| 091 (material3) | 098 | 오탐 2건 발견, 스킬 자체 보강 |
| 092 (proguard) | 100 | 실질 이슈 0건 |

세 스킬을 095~097일차 기준으로 전부 재실행해서, 098일차에서 발견된 오탐 외에는 별다른 문제가 없다는 걸 확인했다. 100일차 자체는 새로운 발견보다는 **검증 스킬 3부작을 마지막까지 확인하고 마무리했다는 완결성**에 의미가 있는 하루였다.

## 오늘 배운 것 — 한 줄 정리

1. 리플렉션 기반 역직렬화를 쓰지 않으면 R8 keep 규칙 문제 자체가 발생하지 않는다 — 095일차의 SAXParser 선택이 이 조건을 충족했다.
2. "이슈 없음"이라는 결과도 실제 릴리즈 빌드로 재확인해야 신뢰할 수 있다.
3. 검증 스킬 3부작(089/091/092)을 같은 기준(095~097 신규 코드)으로 전부 재실행해보면, 어디에 문제가 있고 어디는 문제가 없는지 한 번에 정리할 수 있다.
