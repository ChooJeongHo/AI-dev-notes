## 목적

129일차 결론은 "지시문만으로 24/24가 멈춰 훅의 증분 효과 판정 불가"였고, 128일차 R5 사고(lint 83 ≠ 86을 "줄었으니 괜찮다"고 해석해 PR·머지까지 진행)가 긴 세션·늦은 발견·해석 여지에서 났을 가능성은 가설로 남았다. 오늘의 질문은 하나였다.

> 128일차에 가까운 조건(긴 세션, 압축, 늦은 발견, 해석 여지)을 만들면 지시문이 처음으로 실패하는가? 실패한다면 훅이 증분 효과를 보이는가?

원칙은 이전과 같다.
- 롤백 조건은 구현 전에 합의하고, 걸리면 해석하지 않고 멈춰서 묻는다. 재정의는 이유와 승인을 남긴다.
- 체커·기준은 본 실행 전에 양성 대조로 검증하고 해시로 동결한다. 동결 후에는 바꾸지 않고, 바꿔야 하면 멈추고 묻는다.
- 확정 / 강하게 시사 / 방향성 증거 / 판정 불가를 구분한다.
- 실제 GitHub 쓰기 0, 전역·저장소 설정 수정 0, 앱 소스 수정 0.
- **129일차 교훈 2개를 R 조건으로 넣었다**: 승인 횟수를 넘는 사전 실행 금지(R13), 파일럿이 포화 구간이면 본 실행으로 넘어가지 않고 멈춰 보고(R12).

## 오늘 배운 것 — 한 줄 정리

1. **길이·압축·분산 출력으로 레버를 더해도 지시문은 포화한다.** 파일럿 C1 A~D 8/8, 본 실행 G 12/12다. 128일차 R5가 긴 세션 때문에 났다는 가설은 이 구성에서는 지지되지 않았다.
2. **강한 "해석 금지" 지시는 일치(Gm)에서도 합산 확인을 거부해 오차단 2/2를 냈다.** 지시문은 사고를 막지만 반대 방향 오류(과잉 정지)를 만들 수 있다(n=2).
3. **늦은 발견은 "측정 금지" 한 줄이 있어야 성립한다.** 없으면 에이전트가 체인 전에 한 줄로 묶어 이미 측정한다(통합 점검 ○1차 무효).
4. **압축을 켜도 규칙이 지워지는 경우를 보지 못했다.** 요약 4개 중 3개가 규칙을 담았고 나머지는 최근 메시지 보존으로 해결됐다. 인위적 압축이라 실제 세션과 다를 수 있다.
5. **실험 중 환경이 바뀐다.** CLI가 자동 업데이트되고(2.1.304→2.1.306) 안전 분류기가 모델을 폴백시킨다(cyber, 9회 중 1회). 버전·모델 기록과 정지 규칙이 필요하고, 폴백이 났다고 프롬프트를 바꿔 피하면 안 된다.
6. **폴백 실행을 단순 제외하면 선택 편향이 생길 수 있다.** 그래서 제외 값과 포함 값을 나란히 보고하는 규칙을 미리 정했다(이번엔 폴백 0건이라 같았다).
7. **파일럿 포화 규칙(R12)이 129일차의 가장 큰 놓침을 막았다.** 규칙으로 넣으니 사람이 다시 설계를 고를 수 있었고 비용도 절반 수준으로 끝났다. 다만 "멈춤=보고·질문"이라 오판 비용이 작다는 점이 이 설계가 통한 이유다.
8. **실측 단가가 나오기 전까지 추정을 믿지 않는다.** 129일차는 4배 과대, 이번엔 통합 점검에서 단계당 토큰을 2배 과소 추정했다. 방향은 반대지만 같은 교훈이다(추정은 실측으로 대체).
9. **포화가 두 번 연속이면 레버를 바꿔야 한다.** 길이·압축·분산 출력은 효과가 없었다. 다음은 규칙을 세션 중간 메시지로 주기, 마감 압박·해제 수단 시나리오처럼 "사람이 규칙을 어기고 싶어지는" 조건이다.
