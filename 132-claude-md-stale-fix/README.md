## 목적

131일차에 이미지 서버 핀을 재구성하면서 `CLAUDE.md`의 :307("핀 상수 4개…")·:314·:315("폰은 YR2라 정상")가 증거와 어긋난다는 것을 두 번 확인했지만, 그 PR의 범위 밖이라 고치지 못했다. 128일차에는 일별 측정 요약을 `DEVLOG.md`로 옮겨 39,964B → 37,178B로 줄였지만, `CLAUDE.md`의 O 섹션(규칙도 이력도 아닌 참조·설명 정보)은 손대지 못했다. 그래서 두 가지를 한 번에 묻는다.

1. **낡은 문구는 몇 건이고 에이전트를 실제로 오도하는가?** "문서가 틀리면 에이전트가 틀린다"를 측정한다.
2. **코드에서 다시 구할 수 있는 표를 지우면 나아지는가, 나빠지는가?**

원칙은 이전과 같다.
- **읽기 → 설계 → 롤백 조건 합의 → 구현 → 평가** 순서. 숫자·날짜 기준이나 롤백 조건이 걸리면 해석하지 않고 멈추고 묻는다. 재정의는 이유를 적고 승인 후에만 한다.
- 질문·정답은 파일럿 전에 해시로 사전 등록하고, 파일럿 데이터는 본 통계에서 뺀다. 채점기는 합성 대조를 통과한 뒤 해시로 고정하고 고정 후에는 수정하지 않는다. 판정 불가 구간과 등급 기준은 실행 전에 선언한다.
- 평가는 `claude -p`에서 `--setting-sources project,local`로 전역 훅·전역 지침을 격리한다.
- 저장소 변경(push·PR·merge)은 변경 내용을 보여 주고 승인을 따로 받는다. 일차 요약은 `CLAUDE.md`가 아니라 `DEVLOG.md`에만 쓴다.
- 요청 URL·키는 출력하지 않고, 기기 설정·온보딩 플래그는 건드리지 않는다. 삭제는 리터럴 경로로, 허락 후에만 한다.

**사용자가 1단계 보고 뒤 정한 4가지**

| 질문 | 선택 | 이유(요약) |
|---|---|---|
| 낡은 문구 수정 범위 | 증거 확정 16건 전부 | 근거가 있는 것만 최소 수정. 핀 클러스터 7건만 고치면 숫자·버전 낡음 9건이 남아 전후 비교가 약해짐 |
