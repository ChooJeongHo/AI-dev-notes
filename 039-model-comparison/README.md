# 039 - 모델별 코드리뷰 비용 vs 품질 트레이드오프 실험

**Haiku / Sonnet / Opus 동일 작업 실행 — 비용·품질·속도 3가지 동시 측정**

---

## 목적

AI 도구 선택에서 가장 현실적인 기준은 품질만이 아니라 **비용 대비 품질**.  
동일한 코드리뷰 작업을 3개 모델에 실행해서 어떤 상황에 어떤 모델을 써야 하는지 수치로 결론 도출.

---

## 실험 조건

- 동일한 CLAUDE.md (경량화 버전, 16,849 bytes)
- 동일한 코드리뷰 요청 (최근 5개 커밋 + 핵심 레이어 대표 파일)
- oh-my-claudecode code-reviewer 플러그인 사용

## 모델별 단독 발견 이슈

**Haiku만 발견**
- ML Kit 타임아웃 없음 (유효한 지적)

**Sonnet만 발견 (Opus/Haiku 모두 놓침)**
- `SavedStateHandle` 미적용 → 프로세스 사망 시 탭 상태 리셋 (HIGH, 실제 회귀)
- `FavoriteFragment` retry 버튼 미연결 + 구독 영구 종료 (HIGH, 기능 버그)
- `WorkManager` ViewModel 직접 주입 → SRP/레이어 위반 (MEDIUM)

**Opus만 발견**
- `stateIn` 정책 의미 차이 (심층 동시성 분석)
- `Mutex` 라이프사이클 불일치

## 핵심 발견

### "점수 높음 ≠ 좋은 리뷰"

Sonnet이 점수는 7.7로 제일 낮았지만, **Opus와 Haiku가 모두 놓친 실제 회귀 버그 2개를 발견**했다.  
점수는 얼마나 엄격하게 평가했는지를 반영하지, 탐지 능력을 반영하지 않는다.

### 모델별 강점

| 모델 | 강점 | 약점 |
|------|------|------|
| Haiku | 빠름 (142s), 표면적 이슈 빠르게 탐지 | 코루틴/Flow 심층 분석 불가 |
| Sonnet | 실제 회귀 버그 탐지 최강 | 점수가 낮게 나옴 (엄격한 기준) |
| Opus | 동시성/Flow 심층 분석 강점 | 가장 비쌈, 일부 회귀 놓침 |

## 느낀 점

"비싼 모델이 항상 낫다"는 가정이 틀렸다.  
Sonnet이 Opus보다 저렴하면서도 실제 회귀 버그 탐지에서 앞섰다.

AI 도구를 잘 쓰는 사람은 무조건 좋은 모델을 쓰는 게 아니라, **작업에 맞는 모델을 선택할 줄 아는 사람**이다.
