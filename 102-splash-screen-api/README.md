# 102 - Splash Screen API 조사 — 마이그레이션할 게 없었던 "진짜" 이유가 101일차와 달랐다

**101일차는 "커스텀 코드가 없어서" 손댈 게 없었지만, 102일차는 "애초에 처음부터 공식 API로 만들어져 있어서" 손댈 게 없었다 — 같은 결론이라도 원인은 완전히 다르다**

---

## 목적

101일차(Predictive Back)와 같은 방식으로, 이번엔 스플래시 화면이 최신 공식 API(androidx.core.splashscreen)를 쓰고 있는지 조사한다.

---

## 작업 1 — 조사: 이미 공식 API를 쓰고 있었다

이미 공식 Splash Screen API(androidx.core:core-splashscreen 1.2.0)를 쓰고 있었다. 커스텀 Activity 방식이었던 적이 아예 없다 — git log로 확인해보니 초기 커밋(e3525fe, 2026-02-05)부터 Theme.SplashScreen 기반 구현이었다.

가이드라인과 대조한 결과:

| 항목 | 결과 |
|---|---|
| Theme.SplashScreen 상속 + postSplashScreenTheme 지정 | 정상 |
| installSplashScreen()이 super.onCreate() 이전에 호출됨 (순서) | 정상 |
| minSdk 24 / targetSdk 36 — compat 라이브러리 호환 범위 | 정상 |
| 아이콘/exit 애니메이션 커스텀 | 없음 — 최소 구성, 애초에 위험 요소가 없는 상태 |

---

## 101일차와 같은 결론, 다른 원인

| | 101일차 (Predictive Back) | 102일차 (Splash Screen) |
|---|---|---|
| 결론 | "손댈 게 없다" | "손댈 게 없다" |
| 원인 | 애초에 커스텀 뒤로가기 코드 자체가 없었음 | 애초에 처음부터 공식 API로 구현되어 있었음 |
| 추가 발견 여부 | 있음 — 리소스 타입 문제(res/anim vs res/animator) 발견해서 실제 개선함 | 없음 — 정말로 조사만 하고 끝남 |

101일차는 "표면적으로는 없어 보였지만 실기기 검증에서 다른 진짜 문제를 찾아낸" 케이스였고, 102일차는 "정말로 문제가 없었던" 케이스다. 겉으로 보이는 결과("코드 수정 없음")는 같아도, 조사 과정에서 나온 발견의 밀도는 다르다.

---

## 작업 3 — 코드 변경 없음이 결과물이었다

아무것도 수정하지 않았다. 기존 구현이 가이드라인에 이미 부합하는 상태에서 불필요한 수정을 만드는 게 오히려 리스크라고 판단해서, "손댈 게 없다"는 결론 자체를 이번 조사의 결과물로 봤다.

실제로 발견된 건 스플래시 코드가 아니라 미교체된 기본 런처 아이콘이었는데, 이건 디자인 자산이 필요한 별개 사안이라 이번 범위에서는 보류했다.

---

## 작업 4 — 실기기 검증 (SM-S926N)

### 콜드 스타트

adb shell am start -W로 측정, TotalTime 718~820ms 수준. 인위적 지연(setKeepOnScreenCondition 등) 없이 정상 전환됨. 라이트 모드 첫 실행 때는 알림 권한 다이얼로그가 스플래시 위에 겹쳐 뜨는 것도 확인했다 — 이건 POST_NOTIFICATIONS 런타임 권한 요청으로 인한 정상 동작이다.

### 다크모드

시스템 다크모드를 켜고(settings put secure ui_night_mode 2) 재측정 — 스플래시 배경(다크 네이비, @color/colorPrimary)이 라이트/다크 동일하게 렌더링됨을 확인했다.

?attr 참조가 아니라 리터럴 색상 참조라 시스템 다크모드에 영향받지 않는 구조인데, 이건 의도된 브랜드 컬러 고정으로 판단했다(버그 아님) — 스플래시 배경색은 앱 정체성을 나타내는 요소라 다크모드와 무관하게 고정되는 게 오히려 자연스러운 설계다.

검증 후 디바이스 다크모드 설정은 원래 값으로 복구했다.

## 오늘 배운 것 — 한 줄 정리

1. "코드 수정 없음"이라는 결론이 나와도, 그 원인이 무엇인지는 매번 확인해야 한다 — 101일차(코드 자체가 없었음)와 102일차(처음부터 잘 되어 있었음)는 겉보기엔 같은 결론이지만 완전히 다른 이유다.
2. 스플래시 배경색이 다크모드에 안 바뀌는 건 항상 버그가 아니다 — 의도적인 브랜드 컬러 고정일 수 있고, 이건 리터럴 색상 참조 vs 테마 속성 참조 여부로 구분할 수 있다.
3. 이미 잘 되어 있는 걸 "굳이 뭔가 고쳐야 한다"는 강박 없이, "확인했고 문제없다"는 결론 자체를 정당한 작업 결과로 받아들이는 것도 중요하다.
4. 조사 중 우연히 발견한 무관한 이슈(런처 아이콘)는, 이번 작업 범위와 무관하면 굳이 지금 처리하지 않고 별도로 남겨두는 것도 맞는 판단이다.
