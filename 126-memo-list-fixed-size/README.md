## 목적

125일차에 메모를 6번 저장해도 목록에 안 나타났다(DB에는 6행). 그때는 `setHasFixedSize(true)` + `wrap_content`를 의심했지만 개행으로 재측정을 일으켜도 나타나지 않아 "가설 미지지"로 접었다. 오늘은 그 결함을 **재현 → 원인 분리 → 방안 비교 → 롤백 조건 합의 → 구현 → 기기 검증** 순서로 다뤘다.

원칙은 이전과 같다.
- 수정 전에 먼저 재현하고 측정한다. 증상과 원인을 분리한다.
- "확정"과 "강하게 시사"를 구분해서 쓴다. 직접 보지 못한 것은 보지 못했다고 쓴다.
- 오늘은 상세 화면의 메모 목록 하나만 고친다. 다른 문제는 발견해도 기록만 한다.
- 롤백 조건은 구현 전에 합의하고, 걸리면 완화하지 않고 멈춰서 선택지를 받는다. 재정의가 필요하면 이유를 적고 명시한다.

## 원인 — 무엇이 "확정"이고 무엇이 "강하게 시사"인가

| 구분 | 내용 |
|---|---|
| **확정** | 한 줄(`setHasFixedSize(true)`)을 지우면 같은 조건에서 측정 **높이/기대 높이가 0/40 → 40/40**이 된다. 저장 직후 표시도 0/40 → 40/40 |
| **강하게 시사** | 메커니즘은 "고정 크기 + `wrap_content`일 때 어댑터 변경이 `requestLayout`을 건너뛰어 다시 재지 않는다"이다. `RecyclerView.java:6197-6204`의 변경 처리 경로(`triggerUpdateProcessor`)가 측정된 "높이 0이 유지됨"과 맞는다. **다만 `requestLayout`이 건너뛰어지는 순간을 직접 관찰하지는 못했다** |

- 증상: 상세 화면에서 메모를 저장하면 DB에는 들어가지만(앞선 날들에서 확인) 입력란 아래 목록이 그려지지 않는다. 메모 0개에서 시작하면 목록 높이가 0px로 남고, 메모가 이미 있으면 목록 높이가 그대로라 새 메모가 화면 밖에 있다.
- 가로로 돌리면 목록이 보인다(재측정이 일어나기 때문). 이것이 "고정 크기가 재측정을 막는다"는 방향과 일치하는 관찰이다.
- 층별 제거(레이어 하나씩 빼며 비교)로 `setHasFixedSize(true)` + `wrap_content` 조합까지 좁혔다.
- 125일차의 가설이 접힌 이유는 **그때의 시험 방법(개행으로 재측정 유도)이 이 경로를 건드리지 못했을 가능성**이다. 이 부분은 원인 규명이 아니라 추정이며, 125일차 시험이 왜 안 먹혔는지는 따로 검증하지 않았다.

## 오늘 배운 것 — 한 줄 정리

1. **접어 둔 가설이 틀린 것이 아니라 시험이 못 닿은 것일 수 있다.** 125일차에 "개행으로 재측정을 일으켜도 안 나타나서 미지지"로 끝냈던 `setHasFixedSize(true)`가 오늘 원인이었다. 가설을 접을 때는 "가설이 틀렸다"와 "내 시험이 그 경로를 못 건드렸다"를 구분해서 적어 두면 다음 날 되돌아올 길이 있다.
2. **증상이 데이터 상태에 따라 달랐다.** 메모 0개에서는 높이 0px로 아예 안 보였고, 메모가 있으면 높이가 그대로라 새 메모가 화면 밖에 있었다. 같은 원인이 두 얼굴로 나타났다.
3. **"확정"과 "강하게 시사"를 나눠 쓴다.** 전후 측정(0/40 → 40/40)은 확정이고, `requestLayout`이 건너뛰어지는 순간은 코드 경로와 측정이 맞을 뿐 직접 보지 못했다.
4. **무효·미수행·실패를 따로 센다.** R7 첫 실행 FAIL 6건이 모두 도구 결함이어서 사전 기준대로 "미수행"으로 분류하고 재실행했다. 기준을 미리 정해 뒀기에 결과를 보고 기준을 바꾸는 일이 없었다.
5. **0이라는 결과에는 양성 대조를 붙인다.** 크래시 0건(`am crash` grep=1 검출), 콜드 레이아웃 diff 0(144줄 검출).
6. **한 줄 수정에도 125일차 수정이 유지되는지 확인했다.** 키보드 올림 217/217(36/36), 1~4줄 48/48을 다시 재서 인접 수정을 깨뜨리지 않았다.
7. **롤백 조건이 오늘은 하나도 안 걸렸다.** 124일차 R1, 125일차 R6 재정의 뒤에 조건을 쓰는 방식을 의식한 결과인지, 변경이 작아서인지는 구분할 수 없다. 한 번의 무사통과를 방식의 성공으로 읽지 않는다.
8. **고친 자리를 지키는 테스트가 없다.** 한 줄 삭제는 주석으로만 지켜진다. 측정 기반 검증의 한계를 "남은 한계"에 적어 두는 것이 다음에 같은 줄을 건드릴 때의 안전장치다.
9. **범위를 지키는 결정이 변경을 +1/−1로 지켰다.** 새 메모를 화면에 들여오는 B안, 같은 패턴의 다른 두 곳은 기록만 했다.
10. **CLAUDE.md가 구조적 한계에 왔다.** 하루 1~1.4KB씩 쌓이는 항목으로는 한도(40,000B)를 오래 못 버틴다. 135일차에 "규칙·경고만 CLAUDE.md, 측정 요약은 README"로 나누는 결정이 필요하다.
